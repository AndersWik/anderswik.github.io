Open in a tab

Some apps are too big for a popup, or must keep running when the user clicks somewhere else. Instead of a popup, the toolbar button can open the app's page in a new tab. That takes a background script.

The manifest

Leave out default_popup, and add a background script. Without a popup, a click on the button fires an event instead.

"action": {
  "default_title": "Asteroids",
  "default_icon": { "16": "icons/icon-16.png", "32": "icons/icon-32.png" }
},
"background": {
  "scripts": ["background.js"],
  "service_worker": "background.js"
}

Firefox reads scripts, Chrome and Edge read service_worker. With both, the same extension loads in all of them.

background.js

// Clicking the toolbar button opens the app in a new tab.
// Firefox has "browser", Chrome and Edge only "chrome".
const api = typeof browser !== "undefined" ? browser : chrome;

api.action.onClicked.addListener(function () {
    api.tabs.create({ url: api.runtime.getURL("index.html") });
});
  • action.onClicked fires when the toolbar button is clicked, but only if there is no popup.
  • runtime.getURL() turns a path in the extension into a full address, like moz-extension://…/index.html.
  • tabs.create() opens a new tab. Opening a tab needs no permission.

Which of our apps open in a tab

  • The keyboard games, like Asteroids, Pong and Space Invaders. Their canvas is 800 pixels wide, and a popup would close the moment you clicked outside it. These were left out of the PWAs since they need a keyboard, but in a desktop browser they work fine.
  • Egg Clock and Countdown, since a timer in a popup stops when the popup closes.
  • ASCII table, a wide table.
  • Vagrantfile Maker, which downloads a file.

In _data/extensions.yml this is open: tab:

- { slug: asteroids, page: pages/games/asteroids.html, name: Asteroids, emoji: "☄️", open: tab }

Debug the background script

A background script has no page to look at. Its console.log() shows up when you click Inspect next to the extension in about:debugging.
