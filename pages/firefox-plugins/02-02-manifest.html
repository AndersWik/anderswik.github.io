Manifest

manifest.json is the only file every extension must have. It must be at the top of the extension's folder and be valid JSON: no comments, and no comma after the last item.

Our 8-ball's manifest

This is the manifest of the Magic 8 Ball extension, made by _scripts/make-extension.py:

{
  "manifest_version": 3,
  "name": "Magic 8 Ball",
  "version": "1.0",
  "description": "Ask a question and shake the Magic 8 Ball for an answer.",
  "homepage_url": "https://www.anderswik.se/games/8-ball/",
  "icons": {
    "16": "icons/icon-16.png",
    "32": "icons/icon-32.png",
    "48": "icons/icon-48.png",
    "96": "icons/icon-96.png",
    "128": "icons/icon-128.png"
  },
  "action": {
    "default_title": "Magic 8 Ball",
    "default_icon": {
      "16": "icons/icon-16.png",
      "32": "icons/icon-32.png"
    },
    "default_popup": "index.html"
  },
  "browser_specific_settings": {
    "gecko": {
      "id": "8-ball@anderswik.se",
      "strict_min_version": "140.0",
      "data_collection_permissions": {
        "required": ["none"]
      }
    }
  }
}

The fields

  • manifest_version always 3 for a new extension.
  • name shown in the add-ons list and on addons.mozilla.org.
  • version one to four numbers with dots, like 1.0 or 1.2.3. Every upload to addons.mozilla.org needs a higher version than the last one.
  • description a short text about the extension.
  • homepage_url a link shown in the add-ons manager.
  • icons icons for the add-ons manager and store, see Icons.
  • action the toolbar button: its tooltip, icon and popup page, see Popup.

browser_specific_settings

Settings only Firefox reads. Other browsers ignore them.

  • id the extension's id. It looks like an email address and must be unique, so use a domain you own, like 8-ball@anderswik.se. Never change it after publishing: Firefox would see a new extension, and users would not get updates.
  • strict_min_version the oldest Firefox the extension runs in.
  • data_collection_permissions what data the extension collects or sends away. addons.mozilla.org asks this of every new extension. Our apps collect nothing, so it is ["none"]. Firefox reads this from version 140, which is why strict_min_version is 140.

Permissions

An extension that uses browser APIs has to ask for them, and the user sees the list when installing. Ask for as little as possible: the more permissions, the more users say no, and the longer a review takes.

"permissions": ["storage", "tabs"],
"host_permissions": ["https://api.example.com/*"]

Our games ask for no permissions at all. Even tabs.create(), used to open an app in a tab, works without the tabs permission.
