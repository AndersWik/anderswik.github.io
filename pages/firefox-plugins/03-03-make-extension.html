Many apps at once

Porting the 8-ball by hand took seven steps. For the 45 games and apps on this site, a Python script does the same steps from a list: _scripts/make-extension.py. It reuses the page reading and icon drawing from the PWA script.

The list

_data/extensions.yml has one line for every app.

#   slug         folder in assets/, and the add-on id <slug>@anderswik.se
#   page         the page the app is made from
#   name         full name (default: the page title)
#   emoji        icon picture
#   label        optional short text under the emoji
#   version      raise it for every new upload to addons.mozilla.org (default 1.0)
#   description  text on the add-on page
#   open         popup (default) or tab
#   width        popup width in pixels (default 360, at most 800)

- { slug: 8-ball, page: pages/games/8-ball.html, name: Magic 8 Ball, emoji: "🎱", description: "Ask a question and shake the Magic 8 Ball for an answer." }
- { slug: colorhex, page: pages/utils/colorhex.html, emoji: "🎨", width: 560 }
- { slug: asteroids, page: pages/games/asteroids.html, name: Asteroids, emoji: "☄️", open: tab }

Run it

$ python3 _scripts/make-extension.py           # All apps
$ python3 _scripts/make-extension.py 8-ball    # Only some apps
8-ball                      17 files  popup  Magic 8 Ball

Run it again after changing a page, an app's files or the list. For every app it writes:

  • _extensions/<slug>/ the folder to load in about:debugging.
  • _extensions/<slug>.zip the file to upload to addons.mozilla.org.

The folder starts with an underscore, so Jekyll leaves it out of the site. The folders and zips are in .gitignore, since the script can make them again. Only _extensions/hello-world/ and _extensions/vendor/ are kept in git.

What it does for every app

  1. Reads the page and cleans the HTML, the same way as for the PWA.
  2. Checks the rules in Content Security Policy and stops on inline scripts, onclick=, eval() and code from other sites.
  3. Copies the files with the same paths as on the site: the app's folder, the page's CSS and JavaScript, style.css and the fonts.
  4. Finds more files by looking for paths like /assets/... in the HTML, CSS and JavaScript it copied. That is how the Vagrant templates and the Memory card pictures come along.
  5. Downloads Bootstrap once into _extensions/vendor/, checks it against its integrity hash, and copies it in.
  6. Draws the icons, writes index.html and manifest.json, and for tab apps background.js.
  7. Zips the folder with manifest.json at the top.

Keep the paths

The trick that keeps the script small: in an extension page, / means the top of the extension. So when /assets/8-ball/8-ball.js is copied to _extensions/8-ball/assets/8-ball/8-ball.js, every path in the HTML, CSS and JavaScript still works, and nothing has to be rewritten.

target = folder / href.lstrip("/")     # /assets/8-ball/8-ball.js -> _extensions/8-ball/assets/8-ball/8-ball.js
target.parent.mkdir(parents=True, exist_ok=True)
shutil.copy2(source, target)

Popup or tab

Each popup was opened in a headless Firefox at 360 pixels to see if it fits:

$ cd _extensions/colorhex
$ python3 -m http.server 8801 &
$ firefox --headless --no-remote --profile /tmp/ff --window-size=800,1000 \
    --screenshot colorhex.png http://localhost:8801/index.html

Most fit. Color Hex got width: 560. The ASCII table, the timers and the 800 pixel keyboard games got open: tab, see Open in a tab. Use a new port for every app, or Firefox shows the last page from its cache.

Add a new app

  1. Make sure all its files are in its folder in assets/ or listed in the page's front matter.
  2. Add a line to _data/extensions.yml.
  3. Run python3 _scripts/make-extension.py <slug>.
  4. Load _extensions/<slug>/manifest.json in about:debugging and test it.
