Content Security Policy

Extensions can do much more than web pages, so Firefox is strict about what code they may run. The rules are a Content Security Policy, CSP, and for Manifest V3 the default is:

script-src 'self'; upgrade-insecure-requests;

In plain words: scripts may only come from files inside the extension. This is the most common reason a ported app does nothing at all.

No inline scripts

A <script> with code in it is blocked. Move the code to a file.

<!-- Blocked -->
<script>
  document.getElementById("go").addEventListener("click", start);
</script>

<!-- Works -->
<script src="start.js"></script>

Our game layout has a small inline script that stops the arrow keys from scrolling the page. The script writes it to its own file, game-keys.js, for the games.

No inline event handlers

onclick, onsubmit and the other on... attributes are inline scripts too.

<!-- Blocked -->
<button onclick="shake()">Shake</button>
// Works: in the .js file
document.getElementById("shake").addEventListener("click", shake);

Also javascript: links, like <a href="javascript:reset()">.

No eval

eval(), new Function() and setTimeout("code as text") turn text into code, and are blocked. Pass a function instead:

setTimeout(function () { showAnswer(); }, 500);   // Not setTimeout("showAnswer()", 500)

No code from other sites

A <script src="https://..."> from a CDN is blocked, since Mozilla can not review code that is not in the zip. Download the file and put it in the extension. Our extensions get their own copy of Bootstrap in vendor/.

Stylesheets and pictures from other sites are not blocked by the CSP, but addons.mozilla.org prefers everything in the zip. It also makes the app work offline.

What is allowed

  • Inline <style> and style="..." attributes.
  • fetch() to other sites, like the API in My IP, if that site allows it with CORS headers. Otherwise add the site to host_permissions.
  • localStorage, canvas, audio and everything else a normal page can use.

How the script checks it

_scripts/make-extension.py stops with an error for each of these before Firefox has a chance to complain:

if re.search(r"<script\b(?![^>]*\bsrc=)[^>]*>", body):
    problems.append("an inline <script> block, move it to a .js file")
handler = re.search(r"\son[a-z]+\s*=", body)
if handler:
    problems.append(f"an inline event handler ({handler.group(0).strip()}...), use addEventListener in the .js file")

All of the games and apps on this site already passed, since they were written with addEventListener from the start.

See the errors

Blocked code fails silently on the page. The reason is in the console: open about:debugging, click Inspect next to the extension, and look for Content-Security-Policy errors.
