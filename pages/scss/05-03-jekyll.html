Sass in Jekyll

Jekyll, which builds this site, has Sass built in. It compiles the SCSS when the site is built, so no separate sass command is needed.

How Jekyll finds the files

site/
├── _config.yml
├── _sass/              # Partials, not copied to the site
│   ├── _variables.scss
│   └── _style.scss
└── css/
    └── main.scss       # Compiled to _site/css/main.css
  • An .scss file outside _sass is compiled only if it starts with front matter, two lines of three dashes. They can be empty.
  • Files in _sass are only used when another file loads them.
---
# Only the main Sass file needs front matter (the dashes are enough)
---
@use 'variables';
@use 'style';

Link the compiled file in the layout, with .css instead of .scss:

{% raw %}
<link rel="stylesheet" href="{{ '/css/main.css' | relative_url }}">
{% endraw %}

Settings

In _config.yml:

sass:
  sass_dir: _sass        # The default
  style: compressed      # expanded is the default

Which Sass

Jekyll 4.3 and newer uses Dart Sass, through jekyll-sass-converter version 3, and understands @use. Older Jekyll, and the version GitHub Pages builds with, uses LibSass, which does not understand @use, math.div() or the module functions. With LibSass, use @import and the old global functions, or build the site with GitHub Actions and a newer Jekyll.

$ jekyll --version
$ bundle exec gem list jekyll-sass-converter

Compile by hand

A site can also compile its SCSS with the sass command and commit the CSS file, so the server does not need Sass at all.

$ sass --style=compressed _sass/_style.scss css/style.css

Pick one of the two ways. If a file in _sass is both compiled by Jekyll through main.scss and by hand to style.css, and both are linked in the layout, the same CSS is downloaded twice.
