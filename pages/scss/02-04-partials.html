Partials and @use

Sass can split the styles into many small files and join them into one CSS file. The browser then only has to download one file.

Partials

A file whose name starts with _ is a partial. It is meant to be loaded by other files and is not compiled to its own CSS file.

scss/
├── style.scss          # Compiled to css/style.css
├── _variables.scss
├── _buttons.scss
└── _header.scss

@use

@use loads a file. Leave out the _ and the .scss. All @use rules have to be at the top of the file.

// style.scss
@use 'variables';
@use 'buttons';
@use 'header';

The CSS from each file is added where the @use is. A file is only included once, even if many files @use it.

Namespaces

Variables, mixins and functions from a file loaded with @use are reached through a namespace, which is the last part of the file name, followed by a dot.

// _variables.scss
$color-accent: #e8b455;
$radius: 12px;
// _buttons.scss
@use 'variables';

.button {
  background: variables.$color-accent;
  border-radius: variables.$radius;
}

Each file has to @use what it needs itself. That a file is loaded in style.scss does not make its variables available in the other files. This way it is always clear where a variable comes from.

A long namespace can be made shorter with as, or removed with as *.

@use 'variables' as v;
@use 'mixins' as *;

.button {
  color: v.$color-accent;
  @include rounded;   // From mixins, without a namespace
}

Private members

Variables, mixins and functions that start with - or _ are private. They can only be used in their own file.

$-base-size: 16px;   // Not available in other files

Configure a file

Variables with !default can be set when the file is loaded, with with.

// _theme.scss
$color-accent: blue !default;
$radius: 4px !default;

.button {
  background: $color-accent;
  border-radius: $radius;
}
// style.scss
@use 'theme' with (
  $color-accent: #e8b455,
  $radius: 12px
);

This is how libraries like Bootstrap let you change their colors without changing their files.

Folders and index files

A folder can have an _index.scss, which is loaded when the folder is used.

scss/
├── style.scss
└── components/
    ├── _index.scss
    ├── _buttons.scss
    └── _cards.scss
// components/_index.scss
@forward 'buttons';
@forward 'cards';
// style.scss
@use 'components';

@forward passes on the variables, mixins and functions of a file, so whoever loads components can use them too, as components.$something. It is used to collect many files behind one @use.

@import

Older code uses @import instead of @use.

@import 'variables';
@import 'buttons';

@import makes every variable available everywhere, with no namespace, and includes a file again each time it is imported. It is deprecated since Dart Sass 1.80 and will be removed in Dart Sass 3. Replace it with @use. The Sass migrator can do it automatically.

$ npx sass-migrator module --migrate-deps scss/style.scss

A plain @import url(...) of a CSS file, like a Google font, is still fine. Sass leaves it as it is for the browser.
