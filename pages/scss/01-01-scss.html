SCSS

Sass is a language that is compiled to CSS. It adds things CSS does not have, or did not have for a long time: variables, nesting, mixins, functions, loops and a way to split the styles into many files. Browsers can not read Sass, so a program, the Sass compiler, turns it into a normal CSS file.

SCSS and Sass

Sass has two syntaxes. SCSS, with the file ending .scss, looks like CSS with curly brackets and semicolons. Every CSS file is also a valid SCSS file, so an old style sheet can be renamed to .scss and changed a little at a time.

$color-accent: #e8b455;

nav {
  a {
    color: $color-accent;
  }
}

The older indented syntax, with the file ending .sass, uses indentation instead of brackets.

$color-accent: #e8b455

nav
  a
    color: $color-accent

Both compile to the same CSS. These notes use SCSS, which is what most projects use.

nav a {
  color: #e8b455;
}

Sass and modern CSS

CSS has caught up with some of what Sass offers. CSS has custom properties and calc(), and browsers now support nesting too. Sass is still useful for splitting the styles into files, for mixins and loops, and since it runs before the browser, for things that should be decided once when the CSS is built.

Dart Sass

The Sass compiler is called Dart Sass. The older Ruby Sass, with the commands sass and scss from the ruby-sass package, and LibSass, used by sassc and node-sass, are no longer maintained. They do not understand the newer features, like @use.
