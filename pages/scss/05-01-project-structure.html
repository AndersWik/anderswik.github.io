Project structure

A small site can have all its SCSS in one file. When it grows, split it into partials in folders, so it is easy to find where something is styled.

A simple structure

scss/
├── style.scss              # Only @use, compiled to css/style.css
├── abstracts/
│   ├── _index.scss
│   ├── _variables.scss     # Colors, fonts, sizes, breakpoints
│   ├── _functions.scss
│   └── _mixins.scss
├── base/
│   ├── _reset.scss
│   └── _typography.scss    # body, headings, links
├── layout/
│   ├── _header.scss
│   ├── _footer.scss
│   └── _grid.scss
├── components/
│   ├── _buttons.scss
│   ├── _cards.scss
│   └── _forms.scss
└── pages/
    └── _home.scss          # Styles for one page only
  • abstracts has no CSS of its own, only variables, functions and mixins. It can be loaded by every other file without adding anything to the CSS.
  • base styles the HTML elements themselves.
  • layout is the big parts of the page.
  • components is the small parts that are used in many places.
  • pages is what is special for one page.

This is a smaller version of the popular 7-1 pattern, which has seven folders and one main file.

The files

// abstracts/_index.scss
@forward 'variables';
@forward 'functions';
@forward 'mixins';
// components/_buttons.scss
@use '../abstracts' as *;

.button {
  padding: rem(8px) rem(16px);
  background: $color-accent;
  border-radius: $radius;
}
// style.scss
@use 'base/reset';
@use 'base/typography';
@use 'layout/header';
@use 'layout/footer';
@use 'layout/grid';
@use 'components/buttons';
@use 'components/cards';
@use 'components/forms';
@use 'pages/home';

The order in style.scss is the order in the CSS. Put general styles first and specific ones last, so the specific ones win when the specificity is the same.

Tips

  • One component per file, with the same name as the class. .card is in _cards.scss.
  • Keep all colors and sizes in _variables.scss. A color written straight in a component is easy to miss when the design changes.
  • Add the compiled CSS to .gitignore if the server builds it, or commit it if the server can not run Sass. Never edit the compiled file by hand, the next build overwrites it.
