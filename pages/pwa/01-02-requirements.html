Requirements

Before a browser offers to install a page, a few things have to be in place. The exact rules differ a little between browsers, but this list works everywhere.

What the browser checks

  • The page is served over HTTPS, or from localhost.
  • The page links to a manifest with at least name or short_name, start_url, display and icons in 192 and 512 pixels.
  • A service worker is registered. Chrome no longer demands one to install, but without it the app does not work offline, so always add it.

HTTPS

Service workers can change every answer from the network, so browsers only allow them on secure pages. GitHub Pages, Netlify and most hosts give you HTTPS for free. A page opened as a file, with an address that starts with file://, does not work.

Test on your own computer

Any small web server works, as long as you open the page on localhost or 127.0.0.1.

$ cd my-app
$ python3 -m http.server 8000     # Open http://localhost:8000/

This site is built with Jekyll, which also serves on localhost. Inside the Vagrant box, open the forwarded port on the host.

$ jekyll serve --host=0.0.0.0 --watch --force_polling     # http://localhost:4000/

An address like http://192.168.56.35:4000 is not secure, so the service worker will not start there. Use localhost instead.

Test on a phone

A phone on the same network reaches your computer by its IP address, which is not secure. Two easy ways around it:

  • Deploy to a host with HTTPS, like GitHub Pages, and test there.
  • With Android and Chrome, connect the phone with USB and open chrome://inspect on the computer. Port forwarding makes localhost:4000 on the phone point to your computer.

Browser support

  • Chrome, Edge, Samsung Internet on Android and desktop show an install button.
  • Safari on iPhone and iPad installs with Share, Add to Home Screen. Safari on Mac uses File, Add to Dock.
  • Firefox runs service workers, so the offline part works, but desktop Firefox does not install apps.
