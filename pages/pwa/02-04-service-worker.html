Service worker

A service worker is a JavaScript file that the browser runs apart from the page. It sits between the app and the network: every request the page makes, for HTML, CSS, JavaScript or images, goes through the worker first. That lets it answer from a cache when there is no connection.

A service worker has no access to the page. It can not read or change document, only listen to events.

Register the worker

The page tells the browser where the worker is. Our apps do it at the end of app.html:

<script>
  // The service worker saves the app so it also works offline.
  if ("serviceWorker" in navigator) {
    navigator.serviceWorker.register("sw.js");
  }
</script>

Calling register on every page load is fine. If the worker is already installed, the browser only checks if sw.js has changed.

Scope

A worker only controls pages in its own folder and below. /assets/calculator/sw.js controls /assets/calculator/app.html but not /games/. That is why every app on this site has its own sw.js next to its app.html. Put the worker in the root of the site if it should control the whole site.

The lifecycle

  1. install runs once for every new version of sw.js. This is where the files are saved in the cache.
  2. activate runs when the new version takes over. This is where old caches are deleted.
  3. fetch runs for every request from the pages the worker controls.

event.waitUntil() tells the browser to wait for a promise before the step is done. If saving a file fails during install, the whole install fails and the old version is kept.

Our service worker

Every app on this site has a worker like this one, from assets/calculator/sw.js. It is made by a script, see Many apps at once.

const CACHE = "calculator-2a1a0259dc";

const FILES = [
    "/assets/calculator/app.html",
    "/assets/calculator/calculator.css",
    "/assets/calculator/calculator.js",
    "/assets/calculator/images/icon-192.png",
    "/assets/calculator/manifest.webmanifest",
    "/css/style.css",
    "https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css"
];

// Save all files when the worker is installed.
self.addEventListener("install", function (event) {
    event.waitUntil(
        caches.open(CACHE)
            .then(function (cache) { return cache.addAll(FILES); })
            .then(function () { return self.skipWaiting(); })
    );
});

// Delete the caches of older versions.
self.addEventListener("activate", function (event) {
    event.waitUntil(
        caches.keys()
            .then(function (names) {
                return Promise.all(names
                    .filter(function (name) { return name.startsWith("calculator-") && name !== CACHE; })
                    .map(function (name) { return caches.delete(name); }));
            })
            .then(function () { return self.clients.claim(); })
    );
});

// Answer from the cache first, and only go to the network for anything else.
self.addEventListener("fetch", function (event) {
    if (event.request.method !== "GET") return;

    event.respondWith(
        caches.match(event.request, { ignoreSearch: true }).then(function (cached) {
            return cached || fetch(event.request);
        })
    );
});

The list of files above is shortened. The real one also has the other icons and the fonts.

  • caches is the Cache API, a store of requests and their answers that the worker and the page can both use.
  • skipWaiting() and clients.claim() make a new version take over at once, see Updates.
  • ignoreSearch: true makes app.html?x=1 match the saved app.html.
  • Only GET requests are cached. A form that posts data goes straight to the network.
