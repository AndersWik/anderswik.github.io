Example: My IP

My IP shows your public IP address by asking the service api.ipify.org. The app itself, the page, CSS and JavaScript, can be cached like any other. The answer can not: it has to come from the network every time. This is how most real apps look, part offline and part online.

The app's own files are cached

The worker caches the files in the app folder, exactly like Coin Flip. So the app opens instantly, also with no network.

The API call is not

The address https://api.ipify.org?format=json is not in the worker's list, so caches.match() finds nothing and the worker passes it on with fetch(). Offline, that fetch fails, and the page has to deal with it.

self.addEventListener("fetch", function (event) {
    if (event.request.method !== "GET") return;

    event.respondWith(
        caches.match(event.request, { ignoreSearch: true }).then(function (cached) {
            return cached || fetch(event.request);    // The API call ends up here
        })
    );
});

Note that ignoreSearch: true ignores everything after ?. That is fine here since the API is never cached, but a cache-first worker for an API with values in the address would give the same answer for every value.

Fail with a message

The app was already written to handle errors, so it did not need changing. From assets/myip/myip.js:

async function showMyIp() {
    ipText.textContent = "Loading...";

    try {
        const response = await fetch("https://api.ipify.org?format=json");

        // fetch() only throws when there is no network. If the service
        // answers with an error, like 503, we have to check that ourselves.
        if (!response.ok) {
            throw new Error("HTTP " + response.status);
        }
        const data = await response.json();
        ipText.textContent = data.ip;
    } catch (error) {
        // No network, or the service is down.
        ipText.textContent = "Could not get your IP";
    }
}

When porting your own app, search for every fetch( and XMLHttpRequest and check that each one has a catch that shows something sensible.

Try again when back online

The browser fires an online event when the connection comes back. An app can use it to try again by itself:

window.addEventListener("online", showMyIp);

if (!navigator.onLine) {
    ipText.textContent = "You are offline";
}

navigator.onLine being true only means there is a network, not that the internet or the service can be reached. Always handle errors from fetch too.

Remember the last answer

Some apps should show the last known data when offline, like a weather app showing yesterday's forecast. Save the answer in localStorage, see Saving data, or use a network first worker for the API.
