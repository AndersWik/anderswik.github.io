Saving data

The service worker saves the app's files. The user's data, like scores, settings or a list, has to be saved by the app itself. On a phone the app is often closed by the system in the background, so anything not saved is lost.

localStorage

The simplest store. It keeps text under a key, also after the app is closed. Turn objects into text with JSON.stringify and back with JSON.parse. It holds a few megabytes, which is plenty for most small apps.

localStorage.setItem("settings", JSON.stringify({ sound: true }));

const settings = JSON.parse(localStorage.getItem("settings"));   // null if nothing saved

Our disc golf score card

The Discgolf score card saves the whole round after every change, so a game survives the phone locking or the app being closed. This is from assets/discgolf/discgolf.js:

// localStorage keeps text in the browser, also after a reload. It can be
// turned off (private windows), so every use is inside try/catch.
function saveState() {
    try {
        localStorage.setItem(STORAGE_KEY, JSON.stringify(state));
    } catch (error) {
        // Not saved, but the app still works until the page is closed.
    }
}

function loadState() {
    try {
        const saved = JSON.parse(localStorage.getItem(STORAGE_KEY));
        // Only use it if it looks like our state, not something old or broken.
        if (saved && Array.isArray(saved.players) && Array.isArray(saved.scores)) {
            return saved;
        }
    } catch (error) {
        // Fall through and start fresh.
    }
    return newState();
}

// Call this after every change to the state.
function changed() {
    saveState();
    render();
}
  • Every access is inside try, since storage can be full or turned off.
  • Saved data is checked before use. An older version of the app may have saved something in another shape.
  • One changed() function both saves and redraws, so no change is forgotten.

Where the data lives

Storage belongs to the origin, the scheme, host and port such as https://www.anderswik.se. All apps on this site share one localStorage, so give each app its own key, like "discgolf-scorecard".

On iPhone, an installed app gets its own storage, apart from Safari. Data saved while using the page in Safari is not there in the installed app.

IndexedDB

For more data, many records or files like pictures, use IndexedDB. It is a real database in the browser, and unlike localStorage it can also be used from the service worker. Its own API is clumsy, so most people use a small wrapper like idb.

Ask to keep the data

When the disk is almost full, the browser may delete stored data from sites. An app can ask to be left alone:

if (navigator.storage && navigator.storage.persist) {
    navigator.storage.persist().then(function (granted) {
        console.log(granted ? "Data will be kept" : "Data may be deleted");
    });
}
