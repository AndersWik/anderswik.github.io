Updates

With a cache first worker the app never asks the network for its files, so how does a new version get out? The answer is sw.js itself. The browser always checks the worker file against the server when the app opens. If even one byte is different, the new worker is installed.

Change the cache name

Changing app.js alone is not enough: sw.js is the same, so nothing happens. Give each version its own cache name. Then sw.js changes, the new worker installs and saves the new files in a new cache.

const CACHE = "hello-v1";   // Change to "hello-v2" when any file changes

It is easy to forget to bump a version by hand. Our script uses a hash of all the app's files as the name instead, so it changes by itself when any file does:

digest = hashlib.sha1()
for href in local:
    digest.update(href.encode())
    digest.update((ROOT / href.lstrip("/")).read_bytes())

cache = f"{slug}-{digest.hexdigest()[:10]}"     # e.g. calculator-2a1a0259dc

Delete the old cache

When the new worker activates, the old cache is no longer needed. Delete every cache that starts with the app's name but is not the current one. The name prefix matters on a site with many apps: the calculator must not delete the caches of the other apps.

self.addEventListener("activate", function (event) {
    event.waitUntil(
        caches.keys().then(function (names) {
            return Promise.all(names
                .filter(function (name) { return name.startsWith("calculator-") && name !== CACHE; })
                .map(function (name) { return caches.delete(name); }));
        })
    );
});

Waiting

By default a new worker waits until every window of the app is closed, so the old and new version never run at the same time. For a phone app that is rarely closed, that can take days.

  • self.skipWaiting() in install lets the new worker activate at once.
  • self.clients.claim() in activate makes it take over the open windows too.

Our apps use both. The page that is already open keeps its old files, and the next time the app is opened it gets the new version. That is safe for small apps where the page is loaded in one go.

Tell the user

A bigger app may want to show "A new version is ready, reload?". The page can listen for a new worker taking over:

navigator.serviceWorker.addEventListener("controllerchange", function () {
    document.getElementById("update-banner").hidden = false;
});

The worker file and HTTP cache

Browsers skip the normal HTTP cache when they check sw.js, so a new worker is found at once. The files the worker saves with cache.addAll() do go through the HTTP cache though. GitHub Pages lets browsers keep files for 10 minutes, so right after a deploy a new worker may save an old copy of a file. Wait a few minutes after deploying before you test, or fetch the files with { cache: "reload" }:

cache.addAll(FILES.map(function (file) { return new Request(file, { cache: "reload" }); }));
