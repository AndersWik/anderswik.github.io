Manifest

The web app manifest is a JSON file that describes the installed app. The page links to it from <head>. The usual file name is manifest.webmanifest, but manifest.json works too.

<link rel="manifest" href="manifest.webmanifest">

Our calculator's manifest

This is the manifest of the Calculator on this site, from assets/calculator/manifest.webmanifest.

{
  "name": "Calculator",
  "short_name": "Calculator",
  "id": "./app.html",
  "start_url": "./app.html",
  "scope": "./",
  "display": "standalone",
  "background_color": "#f3f4f6",
  "theme_color": "#1b1d21",
  "icons": [
    { "src": "images/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "images/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "images/icon-maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}

The fields

  • name the full name, shown in the install dialog and the app list.
  • short_name shown under the icon on a home screen. Keep it under about 12 characters, or it gets cut off.
  • start_url the page that opens when the app starts.
  • scope the pages that belong to the app. A link outside the scope opens in the normal browser.
  • id what the browser uses to tell apps apart. If it is missing start_url is used. Set it once and never change it, or the browser sees a new app.
  • display how the window looks, see below.
  • background_color the color of the splash screen while the app starts.
  • theme_color the color of the title bar. Use the same color in <meta name="theme-color"> in the page.
  • icons see Icons.

Paths are relative to the manifest

start_url, scope, id and the icon paths are read relative to where the manifest file is, not the page. Our apps live in /assets/<app>/, so "./" means only that folder. That gives every app its own scope, and many apps can live on the same site without getting in each other's way.

Display

  • standalone its own window with no address bar. This is what most apps use.
  • fullscreen hides the status bar too. Good for games.
  • minimal-ui like standalone, with a few browser buttons such as back and reload.
  • browser a normal browser tab, so it does not really feel installed.

CSS can check how the app is shown, for example to hide a "Install" hint when it is already installed:

@media (display-mode: standalone) {
    .install-hint { display: none; }
}

More fields

  • description a longer text about the app
  • orientation such as "portrait", to lock the screen
  • screenshots pictures shown in a richer install dialog on Android and desktop
  • shortcuts extra entries when you long press the icon
