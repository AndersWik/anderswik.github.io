Port your app

If you already have a JavaScript app that runs in the browser, most of the work is done. Turning it into a PWA is a checklist: make the page stand on its own, list its files, and add the manifest and service worker from Hello World.

1. Does it work on a phone?

Most installs happen on phones, so check this first.

  • The page has <meta name="viewport" content="width=device-width, initial-scale=1">.
  • Buttons are big enough to tap, and nothing needs a mouse hover.
  • Nothing needs a keyboard. This is why games like Asteroids and Pong on this site are not apps: they are played with the arrow keys. The list of what was left out and why is at the top of _data/pwa.yml.

2. Give it a page of its own

On a site, the app is usually part of a bigger page with a menu, header and footer. An installed app opens in its own window, so those links to the rest of the site get in the way, and they would lead out of the app's scope anyway. Make a clean page that only has the app.

On this site each app's normal page is still where the app is edited, and a script makes the clean app.html from it. See Coin Flip.

3. Fix the paths

Paths work the same in the app as on the site, but check two things:

  • Template code, like Jekyll's {% raw %}{{ site.baseurl }}{% endraw %}, has to be turned into plain paths in the app's page.
  • Paths in manifest.webmanifest are relative to the manifest, and paths in sw.js are relative to the worker. Absolute paths like /assets/coin-flip/coin-flip.js are easiest to get right.

4. List every file

The worker can only work offline with files it has saved. Open DevTools, Network, reload the page and write down every file it loads: HTML, CSS, JavaScript, images, fonts and sounds. Files a script loads later, like an image shown after a button is pressed, are easy to miss.

$ find assets/coin-flip -type f      # Everything in the app's folder
assets/coin-flip/coin-flip.css
assets/coin-flip/coin-flip.js
assets/coin-flip/images/favicon.svg
assets/coin-flip/images/head.svg
assets/coin-flip/images/tails.svg

Remember files outside the folder too, like the site's stylesheet and the fonts it loads.

5. Files from a CDN

Our apps use Bootstrap from cdn.jsdelivr.net. Files from another site can be cached like any other, just put the full address in the list. The other site has to allow it with CORS headers, which all big CDNs do.

const FILES = [
    "/assets/coin-flip/app.html",
    "/assets/coin-flip/coin-flip.js",
    "https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css"
];

Or copy the file into your own site, so the app does not depend on someone else's server.

6. Add the manifest, icons and worker

Copy them from Hello World, change the name, colors and file list, and link them from the app's page. See Manifest, Icons and Service worker.

7. Save the user's data

If the app has state worth keeping, like a score or settings, save it in localStorage. See Saving data.

8. Decide what needs the network

Anything that calls a server will fail offline. Show a clear message instead of a broken page. See My IP.

9. Test it

Install it, turn off the network and use every part of the app. See DevTools.
