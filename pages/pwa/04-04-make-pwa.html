Many apps at once

Doing the steps in Coin Flip by hand for 30 apps would be slow, and every time a game changed its app.html and file list would have to be updated too. Instead this site has a Python script, _scripts/make-pwa.py, that makes everything from a list.

The list

_data/pwa.yml has one line for every app. Jekyll reads the same file to show the Install as an app links.

#   slug        folder in assets/ (and the app's id)
#   page        the page the app is made from
#   name        full name (default: the page title)
#   short_name  name under the icon on a home screen, max about 12 characters
#   emoji       icon picture
#   label       optional short text under the emoji, for apps with the same emoji

- { slug: coin-flip, page: pages/games/coin-flip.html, short_name: Coin Flip, emoji: "🪙" }
- { slug: calculator, page: pages/utils/calculator.html, short_name: Calculator, emoji: "🧮" }
- { slug: reversi-ai, page: pages/games/reversi-ai.html, short_name: Reversi AI, emoji: "🌗", label: AI }

Run it

$ sudo apt install python3-yaml python3-pil fonts-noto-color-emoji
$ python3 _scripts/make-pwa.py              # All apps
$ python3 _scripts/make-pwa.py coin-flip    # Only some apps
coin-flip                   16 files  Coin Flip

Run it again after changing a page, any file in an app's folder or the list. Then build and deploy the site as usual.

What it does for every app

  1. Reads the page. Splits the Jekyll page into front matter and HTML. The css and js lists in the front matter say which files the app needs.
  2. Cleans the HTML. Removes the link to the tutorial and {% raw %}{{ site.baseurl }}{% endraw %}. If any other Liquid tag is left it stops with an error, since it can not run Jekyll.
  3. Draws the icons from the emoji, see Icons.
  4. Writes app.html with the head, the cleaned HTML, the scripts and the service worker registration. Bootstrap's JavaScript is only added if the HTML uses it, like an accordion.
  5. Writes manifest.webmanifest.
  6. Writes sw.js with every file in the app's folder, the page's CSS and JavaScript, and the site files every app uses. It checks that each file exists, so a typo is found now and not when a user is offline.

Reading the front matter

def read_page(path):
    """Return the front matter (a dict) and the HTML after it."""
    text = path.read_text(encoding="utf-8")
    match = re.match(r"^---\n(.*?)\n---\n(.*)$", text, re.S)
    if not match:
        sys.exit(f"{path}: no front matter")
    return yaml.safe_load(match.group(1)) or {}, match.group(2)

Finding the files to cache

local = sorted(
    "/" + str(path.relative_to(ROOT))
    for path in folder.rglob("*")
    if path.is_file() and path.name not in SKIP_FILES
)
for href in css + js + SITE_FILES:
    if href not in local:
        local.append(href)
for href in local:
    if not (ROOT / href.lstrip("/")).is_file():
        sys.exit(f"{slug}: {href} does not exist")

The same list is hashed to make the cache name, so a new version is picked up by itself, see Updates.

Add a new app

  1. Make sure the app works on a phone without a keyboard, and that all its files are listed in the page's front matter or are in its folder in assets/.
  2. Add a line to _data/pwa.yml with a slug that matches its folder, and pick an emoji.
  3. Run python3 _scripts/make-pwa.py <slug>.
  4. Open /assets/<slug>/app.html on localhost, install it and test it offline, see DevTools.

Why not a plugin?

There are Jekyll plugins and tools like Workbox that make service workers. GitHub Pages only runs a few approved plugins, and a small script that you can read in one sitting is easier to understand than a tool. For a bigger app built with a bundler like Vite, vite-plugin-pwa does the same job.
