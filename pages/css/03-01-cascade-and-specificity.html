Cascade and specificity

When several rules set the same property on the same element, the cascade decides which one wins.

1. Importance

A declaration with !important wins over normal declarations:

p { color: red !important; }

Avoid it. The only way to override it is another !important, and soon everything has one.

2. Specificity

The more specific selector wins. Specificity is counted in three columns, id, class and type, and compared from the left:

p { }                  /* 0-0-1 */
.note { }              /* 0-1-0 */
p.note { }             /* 0-1-1 */
#intro { }             /* 1-0-0 */
#intro .note p { }     /* 1-1-1 */
  • id: each #id.
  • class: each class, attribute selector and pseudo-class.
  • type: each element name and pseudo-element.

1-0-0 wins over 0-9-9: one id is stronger than any number of classes. A style attribute wins over all of them.

3. Order

If the specificity is the same, the rule that comes last wins:

.button { background-color: blue; }
.button { background-color: green; }   /* this one wins */

Tips

  • Use classes, so most rules have the same specificity and the order decides.
  • If a rule doesn't work, the developer tools show it crossed out, and which rule won.
  • :where() has specificity 0, which makes rules that are easy to override.
