Code and syntax highlighting

Code is shown in a monospace font and nothing inside it is formatted as Markdown. Use inline code for short commands in a sentence and code blocks for longer pieces.

Inline code

Wrap the code in backticks.

Run `ls -la` to list all files.

Backticks inside inline code

Use two backticks around the code, with a space inside if the code starts or ends with a backtick.

``Use `git status` here``
`` `backticks` ``

Fenced code block

Put three backticks on the line before and after the code. Three tildes ~~~ also work.

```
sudo apt update
sudo apt upgrade
```

~~~
sudo apt update
~~~

Syntax highlighting

Write the language after the first backticks to color the code.

```bash
echo "Hello"
```

```python
def hello():
    print("Hello")
```

```javascript
console.log("Hello");
```

Common language names

bash  sh  shell  console
html  css  scss  javascript  js  typescript  ts  json  yaml  xml
python  ruby  php  java  c  cpp  csharp  go  rust
sql  markdown  diff  dockerfile  ini  text  plaintext

Show changes with diff

Lines starting with + are shown as added and lines with - as removed.

```diff
- color: red;
+ color: blue;
```

Indented code block

The original way to write a code block is to indent every line with four spaces or a tab. It cannot have a language, so fences are usually better.

Some text.

    sudo apt update
    sudo apt upgrade

Code block inside a code block

Use more backticks on the outer fence than on the inner one.

````markdown
```bash
ls -la
```
````

More about code

  • Leave an empty line before and after a code block.
  • Inside a list, indent the fences as much as the item text.
  • GitHub uses Linguist for the language names.
  • Diagrams can be written in code blocks too, see GitHub extras.
