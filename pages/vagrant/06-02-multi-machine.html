Multi-machine

One Vagrantfile can describe several machines, for example a web server and a database server. This makes it easy to test applications that run on more than one server.

Define the machines

Each machine gets a name with config.vm.define and its own settings. Settings outside the blocks, like the box here, are shared by all machines.

Vagrant.configure("2") do |config|
  config.vm.box = "bento/ubuntu-24.04"

  config.vm.define "web" do |web|
    web.vm.hostname = "web"
    web.vm.network "private_network", ip: "192.168.56.11"
  end

  config.vm.define "db" do |db|
    db.vm.hostname = "db"
    db.vm.network "private_network", ip: "192.168.56.12"
  end
end

Both machines are on the same private network, so web can reach the database at 192.168.56.12.

Manage the machines

Commands without a name work on all machines. Add a name to work on one.

$ vagrant up
$ vagrant status
$ vagrant ssh web
$ vagrant halt db

Several machines with a loop

The Vagrantfile is Ruby, so a loop can create many similar machines.

(1..3).each do |i|
  config.vm.define "node#{i}" do |node|
    node.vm.network "private_network", ip: "192.168.56.2#{i}"
  end
end

More about multi-machine

  • primary: true makes a machine the default for commands like vagrant ssh
  • autostart: false stops a machine from starting with a plain vagrant up
