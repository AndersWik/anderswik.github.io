Escaping and sanitizing

Data that comes from users, the database or other sites can contain HTML or JavaScript. If it is printed as it is, someone can run their own script on the site, an attack called cross-site scripting (XSS). The rule is: sanitize data when it comes in, escape it when it goes out.

Escape output

Choose the function from where the value is printed.

<h2><?php echo esc_html( $title ); ?></h2>
<input type="text" value="<?php echo esc_attr( $name ); ?>">
<a href="<?php echo esc_url( $link ); ?>">Link</a>
<div><?php echo wp_kses_post( $html ); ?></div>
<script>var data = <?php echo wp_json_encode( $data ); ?>;</script>
FunctionUse for
esc_html()Text inside an element. < becomes &lt;
esc_attr()The value of an attribute
esc_url()href and src. Removes javascript: links
wp_kses_post()HTML, keeping only the tags allowed in a post
wp_json_encode()Values for JavaScript

Template tags like the_title() and the_content() already make their output safe. The get_ functions and our own variables need escaping.

Sanitize input

Clean data from forms before it is saved.

<?php
$name  = sanitize_text_field( wp_unslash( $_POST['name'] ?? '' ) );   // Plain text on one line
$email = sanitize_email( wp_unslash( $_POST['email'] ?? '' ) );
$text  = sanitize_textarea_field( wp_unslash( $_POST['message'] ?? '' ) );
$id    = absint( $_POST['id'] ?? 0 );                                 // A positive whole number

WordPress adds backslashes before quotes in $_POST, $_GET and $_COOKIE. wp_unslash() removes them.

Nonces

A nonce is a token that proves a form was sent from our own site, and not from another site the user visited while logged in. Print it in the form.

<form method="post">
  <?php wp_nonce_field( 'nerdy_save_settings', 'nerdy_nonce' ); ?>
  <input type="text" name="name">
  <button type="submit">Save</button>
</form>

Check it, and that the user is allowed to do the change, before anything is saved.

<?php
if ( isset( $_POST['nerdy_nonce'] ) ) {
  check_admin_referer( 'nerdy_save_settings', 'nerdy_nonce' ); // Stops if the nonce is wrong

  if ( ! current_user_can( 'manage_options' ) ) {
    wp_die( 'Not allowed.' );
  }

  update_option( 'nerdy_name', sanitize_text_field( wp_unslash( $_POST['name'] ) ) );
}

Database queries

Use $wpdb->prepare() for SQL with values from outside, never put a variable straight into the SQL string. It works like the prepared statements on the PHP MySQL page.

<?php
global $wpdb;

$posts = $wpdb->get_results(
  $wpdb->prepare( "SELECT ID, post_title FROM {$wpdb->posts} WHERE post_author = %d AND post_status = %s", $author_id, 'publish' )
);
