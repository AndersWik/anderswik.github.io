WordPress in a subdirectory

In a normal install, WordPress core and our own code are mixed in the same folders. For a project in version control it is cleaner to keep core in its own folder, wp, and our themes and plugins in a wp-content folder next to it. Core can then be replaced as a whole, for example by Composer, and is not added to git.

public_html/
├── index.php          # Ours, loads WordPress from wp/
├── wp-config.php      # Ours
├── .htaccess
├── wp/                # WordPress core, not in git
│   ├── wp-admin/
│   ├── wp-includes/
│   └── ...
└── wp-content/        # Ours
    ├── themes/
    ├── plugins/
    └── uploads/

The site is still at http://example.com, but the dashboard is at http://example.com/wp/wp-admin/.

Move core

Install WordPress as usual. Create a folder called wp and move all the WordPress files into it, except these two:

  • wp-config.php
  • index.php

Keep .htaccess in the root too. WordPress finds wp-config.php one folder above core by itself.

index.php

Every request starts in the root index.php, which loads WordPress. Change the path to point to the wp folder.

<?php
define( 'WP_USE_THEMES', true );
require __DIR__ . '/wp/wp-blog-header.php';

wp-config.php

ABSPATH is the folder that core is in. At the bottom of wp-config.php, change

if ( ! defined( 'ABSPATH' ) ) {
  define( 'ABSPATH', __DIR__ . '/' );
}

to

if ( ! defined( 'ABSPATH' ) ) {
  define( 'ABSPATH', __DIR__ . '/wp/' );
}

The addresses

WordPress has two addresses. WP_HOME is where visitors see the site. WP_SITEURL is where the core files are.

define( 'WP_HOME', 'http://example.com' );
define( 'WP_SITEURL', 'http://example.com/wp' );

The same values are stored in the database, as home and siteurl in wp_options. When they are set in wp-config.php the database values are ignored and the fields are locked under Settings → General. Instead of wp-config.php, the database can be changed, see change site URL.

The content folder

Create a new wp-content folder in the root, next to index.php, with the folders themes and plugins. Git does not keep empty folders, so put an empty .gitkeep file in each.

$ mkdir -p wp-content/themes wp-content/plugins
$ touch wp-content/themes/.gitkeep wp-content/plugins/.gitkeep

Then tell WordPress where it is. WP_CONTENT_DIR is the path on the server, WP_CONTENT_URL is the address in the browser.

define( 'WP_CONTENT_DIR', __DIR__ . '/wp-content' );
define( 'WP_CONTENT_URL', WP_HOME . '/wp-content' );

__DIR__ is the folder of wp-config.php. It is better than $_SERVER['DOCUMENT_ROOT'], which is empty when WordPress is run from the command line, like with WP-CLI. These lines have to come before wp-settings.php is loaded at the bottom of the file.

Updates and the file editor

When the code is in git, changes should be made in git and not on the server.

define( 'DISALLOW_FILE_EDIT', true );          // Remove the theme and plugin editors from the dashboard
define( 'AUTOMATIC_UPDATER_DISABLED', true );  // Do not update core, themes and plugins automatically

With automatic updates off, someone has to update WordPress. Do it often, most updates fix security problems.

.gitignore

.DS_Store
/wp
/wp-content/uploads

Whether uploads should be in git depends on the project. Images uploaded by editors on the live site are not in the repository, so they are often backed up separately and left out.
