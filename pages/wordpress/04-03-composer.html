Composer

Composer is the package manager for PHP. With Composer, WordPress core and the plugins are listed in composer.json with their versions, and composer install downloads them. Only our own code and composer.json are kept in git. This builds on the subdirectory setup.

WordPress core

WordPress is not on Packagist itself, but the package johnpbloch/wordpress is a copy of every release. roots/wordpress is another one that works the same way.

$ composer init
$ composer require johnpbloch/wordpress

It installs core in a folder called wordpress. To use the wp folder from the subdirectory setup instead, set wordpress-install-dir in composer.json before installing.

Plugins from wpackagist

wpackagist.org is a Composer repository with every plugin and theme from wordpress.org. Add it under repositories. The plugins get the names wpackagist-plugin/<slug> and the themes wpackagist-theme/<slug>, where the slug is the last part of the plugin's URL on wordpress.org.

$ composer require wpackagist-plugin/query-monitor

composer.json

{
  "name": "anderswik/example-site",
  "repositories": [
    {
      "type": "composer",
      "url": "https://wpackagist.org",
      "only": ["wpackagist-plugin/*", "wpackagist-theme/*"]
    }
  ],
  "require": {
    "php": ">=8.1",
    "composer/installers": "^2.0",
    "johnpbloch/wordpress": "^6.8",
    "wpackagist-plugin/query-monitor": "^3.16"
  },
  "extra": {
    "wordpress-install-dir": "wp",
    "installer-paths": {
      "wp-content/plugins/{$name}/": ["type:wordpress-plugin"],
      "wp-content/themes/{$name}/": ["type:wordpress-theme"]
    }
  },
  "config": {
    "allow-plugins": {
      "composer/installers": true,
      "johnpbloch/wordpress-core-installer": true
    }
  }
}
  • only makes Composer look for wpackagist-* packages in wpackagist only, and nothing else there.
  • wordpress-install-dir is the folder for core.
  • composer/installers reads installer-paths and puts plugins and themes in wp-content instead of vendor.
  • allow-plugins is needed since Composer 2.2. Composer asks before it runs code from a package, and these two packages are the ones that move the files.

Then install everything, and update to newer versions later with composer update.

$ composer install
$ composer update

composer install uses the exact versions in composer.lock. Keep composer.lock in git, so every server gets the same versions.

Autoloading

To use other PHP packages from Composer in themes and plugins, load Composer's autoloader at the top of wp-config.php.

require_once __DIR__ . '/vendor/autoload.php';

__DIR__ is the folder of wp-config.php. If vendor is one folder up, outside the public folder, use dirname( __DIR__ ) . '/vendor/autoload.php'. Keeping vendor outside the public folder means its files can not be opened in the browser.

.gitignore

Everything Composer installs can be installed again, so it is not added to git. Our own theme and plugin are kept with !.

.DS_Store
/vendor
/wp
/wp-content/plugins/*
!/wp-content/plugins/nerdy-*
/wp-content/themes/*
!/wp-content/themes/nerdy
/wp-content/uploads
