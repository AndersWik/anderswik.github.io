Environment variables

The same code runs on a laptop, a staging server and the live server, but the database login and the URL are different on each one. Passwords should not be in git either. Instead of writing the values in wp-config.php, read them from environment variables that are set on each server.

Read the variables

define( 'DB_NAME', getenv( 'WP_DB_NAME' ) );
define( 'DB_USER', getenv( 'WP_DB_USER' ) );
define( 'DB_PASSWORD', getenv( 'WP_DB_PASSWORD' ) );
define( 'DB_HOST', getenv( 'WP_DB_HOST' ) );

define( 'WP_HOME', getenv( 'WP_HOME' ) );
define( 'WP_SITEURL', getenv( 'WP_SITEURL' ) );

define( 'AUTH_KEY', getenv( 'WP_AUTH_KEY' ) );
define( 'SECURE_AUTH_KEY', getenv( 'WP_SECURE_AUTH_KEY' ) );
define( 'LOGGED_IN_KEY', getenv( 'WP_LOGGED_IN_KEY' ) );
define( 'NONCE_KEY', getenv( 'WP_NONCE_KEY' ) );
// ...and the same for the four salts

define( 'WP_DEBUG', filter_var( getenv( 'WP_DEBUG' ), FILTER_VALIDATE_BOOLEAN ) );
  • Use getenv(). The $_ENV array is often empty, since many PHP installs leave it out (variables_order in php.ini).
  • Environment variables are always strings. The string "false" is true in PHP, so WP_DEBUG would always be on. filter_var( ..., FILTER_VALIDATE_BOOLEAN ) turns "true", "1" and "on" into true, and everything else into false.

Set the variables in .htaccess

With Apache, SetEnv in the .htaccess file in the root sets a variable for PHP. Apache never sends .htaccess to the browser, but keep the file out of git, since it has the passwords.

SetEnv WP_DB_NAME wordpress
SetEnv WP_DB_USER wordpress
SetEnv WP_DB_PASSWORD a-strong-password
SetEnv WP_DB_HOST localhost
SetEnv WP_HOME http://example.com
SetEnv WP_SITEURL http://example.com/wp
SetEnv WP_AUTH_KEY put-a-long-random-string-here
SetEnv WP_SECURE_AUTH_KEY put-a-long-random-string-here
SetEnv WP_LOGGED_IN_KEY put-a-long-random-string-here
SetEnv WP_NONCE_KEY put-a-long-random-string-here
SetEnv WP_DEBUG false

The names have to be exactly the same as in getenv(). SetEnv in .htaccess only works if the virtual host allows it with AllowOverride FileInfo or AllowOverride All. It can also be put straight in the virtual host.

Set the variables for the server

On Red Hat, CentOS and Fedora, Apache reads variables from /etc/sysconfig/httpd when it starts. On Debian and Ubuntu the file is /etc/apache2/envvars, with export before each line.

# /etc/sysconfig/httpd
WP_DB_PASSWORD=a-strong-password
mydocroot=/var/www/public_html

These variables can be used in the Apache config with ${...}.

<VirtualHost *:80>
  DocumentRoot ${mydocroot}
  PassEnv WP_DB_PASSWORD
</VirtualHost>

They are not sent to PHP by themselves. PassEnv passes a variable from Apache's environment on to PHP. Restart Apache after a change with sudo systemctl restart httpd.

Different settings for each environment

One variable can tell which server the code runs on. WordPress has its own constant for it, WP_ENVIRONMENT_TYPE, with the values local, development, staging and production.

define( 'WP_ENVIRONMENT_TYPE', getenv( 'WP_ENV' ) ?: 'production' );

switch ( WP_ENVIRONMENT_TYPE ) {
  case 'local':
  case 'staging':
    define( 'WP_DEBUG', true );
    define( 'WP_DEBUG_DISPLAY', true );
    break;

  default:
    define( 'WP_DEBUG', false );
    define( 'DISALLOW_FILE_MODS', true ); // No plugin or theme installs from the dashboard
}

?: 'production' uses production if the variable is missing, so a forgotten variable never turns on debugging on the live site. In themes and plugins, wp_get_environment_type() returns the value.

<?php if ( 'production' !== wp_get_environment_type() ) : ?>
  <div class="test-banner">Test site</div>
<?php endif; ?>

A .env file

On hosts where environment variables can not be set, a common alternative is a .env file that is not in git, read by the vlucas/phpdotenv package from Composer.
