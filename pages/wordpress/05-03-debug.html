Debug

By default WordPress hides PHP errors. A broken theme or plugin can show only a white page, or "There has been a critical error on this website". Turn on debugging in wp-config.php to see what is wrong.

Debug constants

Put these above the line /* That's all, stop editing! */.

define( 'WP_DEBUG', true );           // Show all PHP errors, warnings and notices
define( 'WP_DEBUG_LOG', true );       // Write them to wp-content/debug.log
define( 'WP_DEBUG_DISPLAY', false );  // Do not print them on the page
define( 'SCRIPT_DEBUG', true );       // Load the full versions of WordPress's CSS and JavaScript, not the minified

Follow the log while using the site:

$ tail -f wp-content/debug.log

wp-content/debug.log can be opened by anyone in a browser. On a public server, give WP_DEBUG_LOG a path outside the public folder instead of true.

define( 'WP_DEBUG_LOG', '/var/log/wordpress/debug.log' );

Turn debugging off again on the live site. The environment page shows how to turn it on for local and staging only.

Write to the log

error_log() writes to the same log. print_r( $value, true ) turns an array or object into a string.

<?php
error_log( 'nerdy: the shortcode ran' );
error_log( print_r( $atts, true ) );

Database queries

SAVEQUERIES saves every database query with how long it took, in $wpdb->queries. It makes the site slower, use it only while debugging.

define( 'SAVEQUERIES', true );

Query Monitor

The Query Monitor plugin shows errors, database queries, hooks, the template that was used and much more in the admin bar. It is the best tool to see what happens on a page.

Recovery mode

When a plugin or theme causes a fatal error, WordPress sends an email to the admin with a link to recovery mode. In recovery mode the broken plugin is paused, so the admin can log in and deactivate it. If the email does not arrive, rename the plugin's folder in wp-content/plugins to deactivate it.
