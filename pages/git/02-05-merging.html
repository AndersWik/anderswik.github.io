Merging

git merge brings the changes from another branch into the current one. A typical flow is to finish a feature on its own branch and then merge it into main.

Merge a branch

Switch to the branch that should receive the changes, then merge.

$ git switch main
$ git merge new-feature

If main has no new commits, Git just moves it forward, this is called a fast-forward. --no-ff always creates a merge commit, which keeps a record of the branch in the history.

$ git merge --no-ff new-feature

Resolve conflicts

If both branches changed the same lines, Git cannot choose and stops with a conflict. git status shows which files have conflicts. In the file, Git marks both versions:

<<<<<<< HEAD
The text on main
=======
The text on new-feature
>>>>>>> new-feature

Edit the file so it looks the way you want and remove the markers. Then stage the file and commit to finish the merge.

$ git add notes.txt
$ git commit

Cancel a merge

$ git merge --abort

Help

-h prints a short summary of the options for git merge. --help opens the full manual page, the same as git help merge.

$ git merge -h
$ git merge --help

More about merging

  • Delete the branch when it is merged, see Branch
  • An alternative to merging is rebase
