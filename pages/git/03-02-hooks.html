Hooks

Hooks are scripts that Git runs automatically at certain moments, for example before a commit. They can check code style, run tests or stop a commit with a bad message.

Where hooks live

Hooks are stored in .git/hooks in each repository. Git creates examples there that end with .sample.

$ ls .git/hooks

Create a hook

The file name decides when the hook runs. This pre-commit hook stops the commit if a file contains the text TODO. If the script exits with anything other than 0, the commit is cancelled.

$ nano .git/hooks/pre-commit
#!/bin/bash
if git diff --cached | grep -q "TODO"; then
  echo "Remove TODO before committing"
  exit 1
fi

The hook must be executable, see chmod.

$ chmod +x .git/hooks/pre-commit

Common hooks

  • pre-commit — before the commit is created
  • commit-msg — checks the commit message
  • pre-push — before pushing, for example to run tests
  • post-merge — after a merge or pull

Share hooks with the team

The .git folder is not committed, so hooks are not shared. Put them in a folder in the repository and tell Git to use it.

$ git config core.hooksPath .githooks

More about hooks

  • Skip the pre-commit and commit-msg hooks once with git commit --no-verify
