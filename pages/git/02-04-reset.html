Reset

git reset moves the branch back to an earlier commit. It is used to undo commits that are not pushed yet.

Undo the last commit, keep the changes

The commit is removed but the changes are kept in your files, so you can fix them and commit again. HEAD~ means the commit before the current one.

$ git reset HEAD~

--soft does the same but keeps the changes staged.

$ git reset --soft HEAD~

Throw away commits and changes

--hard also resets the files, so all changes after that commit are lost. Use it with care.

$ git reset --hard a1b2c3d

Throw away all local commits and make the branch match the remote.

$ git fetch
$ git reset --hard origin/main

Undo a reset

Git remembers where the branch has been. reflog lists it, and you can reset back to the hash from before.

$ git reflog
$ git reset --hard a1b2c3d

Help

-h prints a short summary of the options for git reset. --help opens the full manual page, the same as git help reset.

$ git reset -h
$ git reset --help

More about reset

  • Find the hash of a commit with git log --oneline
  • To undo a commit that is already pushed, use git revert instead. It creates a new commit that undoes the changes
