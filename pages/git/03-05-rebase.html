Rebase

git rebase moves commits so they start from another point. It gives a straight history instead of merge commits. Interactive rebase also lets you edit, combine and reorder commits.

Update a branch with main

Move the commits of your branch so they start from the latest main.

$ git switch new-feature
$ git rebase main

Interactive rebase

Edit the last three commits. Git opens an editor with one line per commit.

$ git rebase -i HEAD~3
pick a1b2c3d Add login page
pick e4f5a6b Fix typo
pick c7d8e9f Add logout button

Change the word at the start of a line to decide what happens to that commit, then save and close the editor.

  • pick — keep the commit as it is
  • reword — keep the commit but change the message
  • edit — stop at the commit so you can change it
  • squash — combine with the commit above and edit the message
  • fixup — combine with the commit above and keep its message
  • drop — remove the commit

Change the author of an older commit

Start an interactive rebase from the commit before the one to change, and mark it with edit. When Git stops, amend the author and continue.

$ git rebase -i a1b2c3d
$ git commit --amend --author="Your Name <you@example.com>" --no-edit
$ git rebase --continue

Conflicts

Resolve them as when merging, then continue. You can always cancel and get back to where you started.

$ git add notes.txt
$ git rebase --continue
$ git rebase --abort

Push after a rebase

Rebase rewrites the commits, so you have to force push. Only rebase commits that others have not based their work on.

$ git push --force-with-lease

Help

-h prints a short summary of the options for git rebase. --help opens the full manual page, the same as git help rebase.

$ git rebase -h
$ git rebase --help
