Make Request

We build a small Postman: pick a method, write a URL, add headers and a body, press Send, and see the status, the time, the headers and the body that come back.

The new ideas are fetch() with all its options, async / await, and CORS: the rule that decides which servers a web page may talk to.

CORS: what a web page may not do

Postman is a program on your computer, and it can call any server. A web page can't. Say you are logged in to your bank, and open some other site. If that site's JavaScript could fetch your bank's pages, it would be sent with your bank's cookies, and it could read your account. So browsers have the same-origin policy: a page may only read responses from its own site.

CORS (Cross-Origin Resource Sharing) is how a server says that other sites are welcome. It answers with a header:

Access-Control-Allow-Origin: *

Without that header the browser still gets the response, but it doesn't give it to your JavaScript. fetch() fails instead. Most public APIs, like GitHub's and jsonplaceholder.typicode.com, send the header. Most normal websites don't.

Some requests are checked before they are sent. A PUT, PATCH or DELETE, a JSON body, or a header like Authorization, makes the browser first send an OPTIONS request, called a preflight, that asks the server if it is OK. If the server doesn't say yes, the real request is never sent.

A few things a web page can never do, whatever the server says:

  • Set some headers, like Cookie, Host, Origin and Referer. The browser sets them itself and quietly drops yours.
  • Use the methods CONNECT and TRACE.
  • Call http:// from a page on https:// (mixed content), except localhost.
  • Read every response header. Only a few simple ones, unless the server lists more in Access-Control-Expose-Headers.

So our tool works with any API that allows CORS, and with your own server on localhost if you turn CORS on there. For everything else, see the Firefox add-on at the end.

Step 2: The headers

fetch() takes headers as a Headers object. We split the text area into lines, and every line at its first :. Only the first, because a value can have : in it, like Authorization: Basic a:b:

function readHeaders() {
    const headers = new Headers();
    headersInput.value.split("\n").forEach(function (line) {
        const colon = line.indexOf(":");
        if (colon > 0) {
            headers.append(line.slice(0, colon).trim(), line.slice(colon + 1).trim());
        }
    });
    return headers;
}

colon > 0 skips empty lines and lines without a name. Headers doesn't care about upper and lower case, so headers.has("content-type") finds Content-Type too.

Step 3: Send it

async function send() {
    errorText.hidden = true;
    const method = methodSelect.value;
    const options = { method: method, headers: readHeaders() };

    if (method !== "GET" && method !== "HEAD" && bodyInput.value !== "") {
        options.body = bodyInput.value;
        if (!options.headers.has("Content-Type")) {
            options.headers.set("Content-Type", "application/json");
        }
    }

    sendButton.disabled = true;
    const started = performance.now();

    try {
        const response = await fetch(urlInput.value.trim(), options);
        const text = await response.text();
        const ms = Math.round(performance.now() - started);
        showResponse(response, text, ms);
    } catch (error) {
        showError("The request failed: " + error.message);
    } finally {
        sendButton.disabled = false;
    }
}

fetch() doesn't wait for the server. It gives back a promise, a value that arrives later. Inside a function marked async, await pauses the function until the value has arrived, without freezing the page. That lets us write the steps in order, like normal code. The response comes in two parts: await fetch() waits for the status and headers, and await response.text() waits for the whole body.

GET and HEAD can't have a body, fetch() throws an error if you give them one. When there is a body and no Content-Type, we say it is JSON, since that is what most APIs want.

performance.now() is a clock in milliseconds that is made for measuring, so the time includes downloading the body.

finally runs whether it worked or not, so the button always comes back.

Step 4: Errors are not what you think

fetch() only throws when there is no response to read: a wrong address, no network, or a CORS block. A 404 or 500 is not an error to fetch(). The server answered, so you get a normal response with response.status 404, and response.ok false. That is what we want in this tool: show every status.

When it does throw, the browser doesn't tell the page why. A CORS block and a typo give the same vague TypeError, on purpose, so a page can't use errors to find out things about other servers. The reason is only written in the browser console. So the best we can do is list the likely reasons:

showError("The request failed: " + error.message + "\n\n" +
    "If the address is right, the server probably doesn't allow CORS. " +
    "The browser console (F12) has the exact reason.");

Don't try mode: "no-cors". It sends the request, but gives you an "opaque" response: status 0, no headers, an empty body. It is only useful when you don't need the answer.

Step 5: Show the response

function showResponse(response, text, ms) {
    statusText.textContent = response.status + " " + response.statusText;
    statusText.className = "status " +
        (response.status >= 400 ? "error" : response.status >= 300 ? "redirect" : "ok");
    timeText.textContent = ms + " ms";
    responseBody.textContent = prettyBody(text);

    let headerLines = "";
    response.headers.forEach(function (value, name) {
        headerLines += name + ": " + value + "\n";
    });
    responseHeaders.textContent = headerLines;

    responseBox.hidden = false;
}

function prettyBody(text) {
    try {
        return JSON.stringify(JSON.parse(text), null, 2);
    } catch (error) {
        return text;
    }
}

JSON from an API is usually one long line. JSON.parse reads it, and JSON.stringify with 2 as the third argument writes it again with two spaces of indent. If the body isn't JSON, JSON.parse throws and we show the text as it is. We use textContent, since the body comes from another server and could be HTML that we must not run.

The finished page puts it all inside send(). The version on this site also has a Cancel button, using an AbortController:

const controller = new AbortController();
fetch(url, { signal: controller.signal });
// later, on Cancel:
controller.abort();   // fetch() throws an error with the name "AbortError"

Step 6: Test it

  • GET https://jsonplaceholder.typicode.com/users/1 gives 200 and pretty JSON.
  • POST to https://jsonplaceholder.typicode.com/posts with the body {"title": "Hello"} gives 201 and the post back with an id.
  • GET https://jsonplaceholder.typicode.com/nothing gives 404, as a response and not an error.
  • GET https://example.com/ fails, since example.com doesn't allow CORS. Open the console (F12) to see the browser say so.
  • Add the header Cookie: a=b and look at the request in the Network tab of the developer tools. It is not there.

Calling any URL: a Firefox add-on

Browser extensions play by different rules. A page inside an extension that has host permission for a site can fetch from it and read the response, CORS or not. The user agrees to that when they install the add-on. So the same page, made into an add-on, works like Postman.

The manifest asks for permission for every site with <all_urls>:

{
  "manifest_version": 3,
  "name": "Make Request",
  "version": "1.0",
  "host_permissions": ["<all_urls>"],
  "content_security_policy": {
    "extension_pages": "script-src 'self'; object-src 'self'"
  }
}

The content_security_policy line is there because the default policy for extension pages also has upgrade-insecure-requests, which turns every http:// request into https://. Without the line, you couldn't call an http API.

The user can turn the permission off in the add-on's settings, so the page checks, and shows a button that asks for it again. permissions.request() has to be called right from a click, or Firefox says no:

const ALL_SITES = { origins: ["<all_urls>"] };

browser.permissions.contains(ALL_SITES).then(function (granted) {
    permissionNote.hidden = granted;
});

permissionButton.addEventListener("click", function () {
    browser.permissions.request(ALL_SITES).then(function (granted) {
        permissionNote.hidden = granted;
    });
});

Some headers, like Host and Content-Length, are still set by the browser in an add-on.

On this site, the add-on is made by _scripts/make-extension.py from the same page as the website. The line in _data/extensions.yml has all_urls: true, which adds the two settings above. See Make an extension for how the rest works.

History and a library

The version on this site also remembers what you did. It keeps every request as a plain object, so the form, the history, the library and the exported file all use the same shape:

{ method: "POST", url: "https://...", headers: [{ name: "Accept", value: "application/json" }],
  bodyType: "json", body: "{...}" }

Two functions turn the form into such an object and back, currentRequest() and applyRequest(request). Then loading a request from the history, from the library or from the last visit is all the same call.

History

Every request that is sent goes first in a list, with the status and time it got. unshift adds to the start of a list, and slice(0, 50) keeps the newest 50, so localStorage doesn't fill up:

function addToHistory(request, status, ms) {
    history.unshift({ ...request, status: status, ms: ms, at: Date.now() });
    history = history.slice(0, 50);
    localStorage.setItem("make-request-history", JSON.stringify(history));
    renderHistory();
}

{ ...request, status: status } makes a new object with everything from request, plus status. Failed and cancelled requests go in the history too, with the status "error" or "cancelled".

Library

The library is a list of requests with a name. The name is the key: saving with a name that is already there replaces that request, so you can change a request and save it again. findIndex gives the position of the first item that matches, or -1:

function putInLibrary(name, request) {
    const entry = { ...request, name: name };
    const index = library.findIndex(function (l) {
        return l.name.toLowerCase() === name.toLowerCase();
    });
    if (index === -1) {
        library.push(entry);
    } else {
        library[index] = entry;
    }
}

Export: make a file to download

A web page can't write files on your computer, but it can offer one for download. A Blob is a piece of data in memory. URL.createObjectURL gives it an address, and a link with the download attribute saves what it points to as a file instead of opening it:

function exportLibrary() {
    const data = { type: "make-request-library", version: 1, requests: library };
    const blob = new Blob([JSON.stringify(data, null, 2)], { type: "application/json" });
    const link = document.createElement("a");
    link.href = URL.createObjectURL(blob);
    link.download = "make-request-library.json";
    document.body.append(link);
    link.click();
    link.remove();
    setTimeout(function () { URL.revokeObjectURL(link.href); }, 1000);
}

revokeObjectURL frees the memory again. The type and version fields say what the file is, so a later version of the tool can read old files.

Import: read a file the user picks

An <input type="file"> lets the user pick a file. We hide it and click it from a normal button, which looks nicer. file.text() reads the file and gives back a promise with its text:

<button type="button" id="import">Import</button>
<input type="file" id="import-file" accept=".json,application/json" hidden>

importButton.addEventListener("click", function () { importFile.click(); });

importFile.addEventListener("change", function () {
    const file = importFile.files[0];
    importFile.value = "";   // so the same file can be picked again
    file.text().then(function (text) {
        const data = JSON.parse(text);
        data.requests.forEach(function (item) {
            const request = cleanRequest(item);
            if (request) {
                putInLibrary(item.name, request);
            }
        });
        saveLibrary();
    });
});

Never trust a file. It may come from someone else, be from an old version, or not be ours at all. cleanRequest checks every field and gives back null for anything it can't use: a method that isn't in the list, a URL that isn't text, headers that aren't a list. The site version also puts JSON.parse in a try, and tells you how many requests were added, updated and skipped. And the names and URLs are shown with textContent, so a file with HTML in it can't run code on the page.

Try this

  • Search the history and the library with a text field above the lists.
  • Add a field for query parameters, and build the URL with new URL() and url.searchParams.set().
  • Show images: if the Content-Type starts with image/, use response.blob() and URL.createObjectURL().
