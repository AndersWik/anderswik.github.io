Code playground

We build a code playground, like a tiny CodePen. There are boxes for HTML, CSS and JavaScript, and one for extra tags in <head>, like libraries. The boxes are put into a template of a whole HTML page, which is shown in an <iframe> next to them. A drop down adds common libraries like Bootstrap and jQuery, and console.log() from your code shows up under the result.

Open the finished code playground · The full tool on this site

The plan

  • Glue the boxes into one long string: a whole HTML page.
  • Show that string in an <iframe> with srcdoc.
  • Lock the iframe in with sandbox, so the code can't reach our page.
  • Add a small script first in the page that sends console.log() back to us with postMessage().

Step 2: A page from four boxes

The result is just text: the start of an HTML page, then each box in its place. We build it as a list of lines and join them with "\n".

function buildPage(code, forPreview) {
    const lines = [
        "<!DOCTYPE html>",
        '<html lang="en">',
        "<head>",
        '<meta charset="utf-8">',
        '<meta name="viewport" content="width=device-width, initial-scale=1">',
        "<title>Playground</title>"
    ];
    if (forPreview) {
        lines.push(CONSOLE_CATCHER);         // see step 5
    }
    lines.push(code.head, "<style>", escapeEnd(code.css, "style"), "</style>",
               "</head>", "<body>", code.html, "<script>");
    const top = lines.join("\n") + "\n";

    return {
        text: top + escapeEnd(code.js, "script") + "\n<\/script>\n</body>\n</html>\n",
        jsFirstLine: top.split("\n").length
    };
}

jsFirstLine is the line of the page where the JavaScript box starts. We need it in step 5 to tell which line an error is on.

Step 3: The closing tag trap

Say someone writes this in the JavaScript box:

console.log("</script>");

The browser reads HTML before it runs any JavaScript. When it sees </script> it ends the script right there, in the middle of the string, and the rest of the code shows up as text on the page. The same goes for </style> in CSS. A backslash before the slash fixes it: <\/script> is not a closing tag to HTML, and to JavaScript "\/" is just "/".

// A closing script tag in the JavaScript would end the <script> early.
function escapeEnd(code, tagName) {
    return code.replace(new RegExp("</" + tagName, "gi"), "<\\/" + tagName);
}

The same trap is in our own code. This page's script is inline too, so every </script> inside it, like in buildPage above, is written <\/script>. Even a comment counts: while writing this tutorial, a comment with </script> in it broke the whole page.

Step 4: Show it in a sandboxed iframe

An <iframe> shows a page inside our page. Its srcdoc takes the HTML as text, so we don't need a file or a server. Setting it loads the page again:

function run() {
    clearTimeout(runTimer);
    consoleList.replaceChildren();          // empty the console
    const page = buildPage(readCode(), true);
    jsFirstLine = page.jsFirstLine;
    preview.srcdoc = page.text;
}

Without sandbox, code in the iframe would run as our site. It could read parent.document, or localStorage where other apps on the site keep their data. With sandbox the iframe is treated as a different site, and only what we list is allowed:

  • allow-scripts run JavaScript, which is the whole point.
  • allow-modals alert(), confirm() and prompt().
  • allow-forms submit forms.
  • allow-popups open links in a new tab.

We leave out allow-same-origin. Together with allow-scripts it would let the code remove its own sandbox.

Step 5: Catch console.log

The iframe's console.log() goes to the browser's developer tools, which are hard to reach on a phone. So we put a small script first in the page. It wraps console.log, warn and error, and listens for errors, and sends everything to us with postMessage():

const CONSOLE_CATCHER = `<script>
(function () {
  function show(value) {
    if (typeof value === "string") return value;
    if (value instanceof Error) return value.name + ": " + value.message;
    try { return JSON.stringify(value); } catch (error) { return String(value); }
  }
  function send(type, values, line) {
    parent.postMessage({ playground: true, type: type, text: values.map(show).join(" "), line: line }, "*");
  }
  ["log", "warn", "error"].forEach(function (type) {
    const original = console[type];
    console[type] = function () {
      send(type, Array.from(arguments));
      original.apply(console, arguments);
    };
  });
  window.addEventListener("error", function (event) {
    send("error", [event.message], event.lineno);
  });
})();
<\/script>`;
  • A template literal, with backticks, can span many lines, which makes it easy to keep a script in a string.
  • JSON.stringify turns objects and lists into text, so console.log({ a: 1 }) shows {"a":1}.
  • The original console.log is still called, so the developer tools show it too.
  • "*" means any receiver. A sandboxed page has no origin we could name.

On our side, we only accept messages from our own iframe:

function receiveMessage(event) {
    if (event.source !== preview.contentWindow || !event.data || !event.data.playground) {
        return;
    }
    addConsoleLine(event.data.type, String(event.data.text), event.data.line);
}

window.addEventListener("message", receiveMessage);

An error's lineno counts lines in the whole page. Take away the line where the JavaScript box starts, and it is the line in the box:

function addConsoleLine(type, text, line) {
    const item = document.createElement("li");
    item.className = type;
    item.textContent = (line >= jsFirstLine ? "Line " + (line - jsFirstLine + 1) + ": " : "") + text;
    consoleList.appendChild(item);
    consoleList.scrollTop = consoleList.scrollHeight;
}

textContent, not innerHTML: a message like "<img src=x onerror=...>" must show as text, not become HTML on our page.

Step 6: Run as you type

Reloading the iframe on every key would flicker and run half written code. Instead we wait until the typing stops. Every key starts the timer again, so run() only happens 600 ms after the last key. This is called a debounce.

function runSoon() {
    clearTimeout(runTimer);
    if (autoRunBox.checked) {
        runTimer = setTimeout(run, RUN_DELAY);
    }
}

Step 7: Libraries

Each library is one or more tags for the head box. The versions are fixed in the address, so a new version can't suddenly break the code:

const LIBRARIES = [
    { name: "Bootstrap 5.3", tags: [
        '<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css">',
        '<script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"><\/script>'] },
    { name: "jQuery 3.7", tags: [
        '<script src="https://cdn.jsdelivr.net/npm/jquery@3.7.1/dist/jquery.min.js"><\/script>'] }
];

The drop down is filled from the list. new Option(text, value) makes an <option>, and the value is the number in the list. When one is picked, its tags are added to the head box, unless they are already there:

function addLibrary() {
    const library = LIBRARIES[Number(librarySelect.value)];
    librarySelect.value = "";               // back to "Add a library…"
    if (!library) {
        return;
    }
    const newTags = library.tags.filter(function (tag) {
        return !headCode.value.includes(tag);
    });
    if (newTags.length > 0) {
        const before = headCode.value.trimEnd();
        headCode.value = (before ? before + "\n" : "") + newTags.join("\n");
        changed();
    }
}

Step 8: Save and download

All four boxes are saved in localStorage on every change, the same way as in the disc golf score card. Download saves the page as a file, without the console catcher. A Blob is a file in memory, and URL.createObjectURL() gives it an address a link can point to:

function download() {
    const blob = new Blob([buildPage(readCode(), false).text], { type: "text/html" });
    const url = URL.createObjectURL(blob);
    const link = document.createElement("a");
    link.href = url;
    link.download = "playground.html";
    document.body.appendChild(link);
    link.click();
    link.remove();
    setTimeout(function () { URL.revokeObjectURL(url); }, 1000);
}

Step 9: The Tab key

In a text box, Tab moves to the next field. In a code box we want it to indent. setRangeText() replaces the selected text, or puts text at the cursor if nothing is selected:

function insertTab(event) {
    if (event.key !== "Tab" || event.shiftKey) {
        return;
    }
    event.preventDefault();
    const box = event.target;
    box.setRangeText("  ", box.selectionStart, box.selectionEnd, "end");
    changed();
}

Now someone using only the keyboard can't Tab out of the box. The tool on this site lets Esc and then Tab leave the box.

Step 10: Test it

  • Click the button in the example. "Hello!" shows in the console.
  • Write console.log({ a: 1, list: [1, 2] }). It shows as JSON.
  • Write notDefined(); on line 3. The console says Line 3: ReferenceError.
  • Write console.log("</script>"). It prints, and nothing breaks.
  • Add jQuery and write $("h1").css("color", "red").
  • Reload the page. Your code is still there.

As an app

The tool on this site is also a PWA, so it can be installed and works offline. Libraries from a CDN still need the network the first time.

Unlike most apps on this site, it is not a Firefox extension. Extension pages may not run inline scripts, and an iframe made with srcdoc gets the same rule, so nothing in the result would run. See Content Security Policy.

Try this

  • Browsers don't all count lines the same way. Make the page ask: put <script>report()</script> just before the JavaScript box, and read the line from new Error().stack. The tool on this site does this.
  • Save the code in the address, like #code=..., so a link can share it. encodeURIComponent() and JSON.stringify() are enough for small examples.
  • Add a drop down of examples: a Bootstrap card, a canvas drawing, a jQuery click.
  • Let the user drag the line between the boxes and the result to make them wider.
