Ssh

ssh (Secure Shell) connects to another computer over an encrypted connection and gives you a terminal on it. It is the standard way to manage Linux servers. Logging in with keys instead of passwords is both safer and more convenient.

Connect to a server

$ ssh user@example.com
$ ssh -p 2222 user@example.com   # other port

Generate Key

ssh-keygen creates a key pair: a private key that stays on your computer and a public key (.pub) that you give to servers and services like GitHub. -C adds a comment, usually your email.

$ ssh-keygen -t rsa -b 4096 -C "user@dev.se"

Ed25519 keys are shorter and are recommended today.

$ ssh-keygen -t ed25519 -C "user@dev.se"

Copy Public to clipboard. pbcopy is a macOS command; on Linux use xclip or just cat the file and copy the text.

$ pbcopy < ~/.ssh/id_rsa.pub
$ xclip -selection clipboard < ~/.ssh/id_rsa.pub

Copy Private to clipboard. Never share the private key with anyone.

$ pbcopy < ~/.ssh/id_rsa

Generate Second Key, for example for a second GitHub account. -f sets the file name.

$ ssh-keygen -t rsa -f ~/.ssh/accountB -C "userk@dev.se"

Copy the key to a server

ssh-copy-id adds your public key to ~/.ssh/authorized_keys on the server, so you can log in without a password.

$ ssh-copy-id user@example.com

SSH config

Edit SSH config. The file ~/.ssh/config stores settings for hosts you connect to often, like which user, port and key to use.

$ ~/.ssh/config
$ nano ~/.ssh/config
Host myserver
    HostName example.com
    User anders
    Port 2222
    IdentityFile ~/.ssh/accountB

After that ssh myserver is enough to connect.

Version

ssh has no --version. -V shows which version of OpenSSH is installed. -v does not show the version, it prints debug messages while connecting.

$ ssh -V

More about ssh

  • The private key must only be readable by you: chmod 600 ~/.ssh/id_rsa
