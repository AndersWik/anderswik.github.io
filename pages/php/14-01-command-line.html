Command line

PHP is not only for web pages. Scripts can be run from the terminal, for example to import data, run scheduled jobs with crontab or build tools.

$ php script.php
$ php -r 'echo PHP_VERSION;'
$ php -a

-r runs code directly and -a starts an interactive shell.

Shebang

With a shebang as the first line, the script can be run like any other program. #!/usr/bin/env php finds php in the PATH, which works on more systems than a fixed path like #!/usr/bin/php.

#!/usr/bin/php
#!/usr/bin/env php
<?php
var_dump($argv);
?>
$ chmod +x script.php
$ ./script.php one two
array(3) {
  [0]=>
  string(12) "./script.php"
  [1]=>
  string(3) "one"
  [2]=>
  string(3) "two"
}

Arguments

$argv is an array with the name of the script and the arguments, and $argc is the number of items in it.

<?php
if ($argc < 2) {
  fwrite(STDERR, "Usage: php greet.php <name>\n");
  exit(1);
}

echo "Hello " . $argv[1] . "\n";

getopt reads options like -v and --name=Anna. One : means the option needs a value.

<?php
$options = getopt("v", ["name:"]);

$verbose = isset($options["v"]);
$name = $options["name"] ?? "World";

echo "Hello $name\n";
$ php greet.php -v --name=Anna
Hello Anna

Input and output

STDIN, STDOUT and STDERR are open from the start. Errors should go to STDERR, so they are not mixed with the output when it is sent on to another program.

<?php
echo "What is your name? ";
$name = trim(fgets(STDIN));
echo "Hello $name\n";
<?php
// Count the lines sent to the script, like: cat file.txt | php count.php
$count = 0;
while (($line = fgets(STDIN)) !== false) {
  $count++;
}
echo $count . "\n";

Exit code

exit(0) means success and any other number means an error. Other programs and shell scripts check this value.

$ php greet.php
Usage: php greet.php <name>
$ echo $?
1

Only run from the command line

A script that should never be run from a browser can check PHP_SAPI.

<?php
if (PHP_SAPI !== 'cli') {
  http_response_code(404);
  exit;
}
