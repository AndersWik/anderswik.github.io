MVC view

The view turns data into HTML. It should not talk to the database or read $_POST, it only prints what it is given. PHP itself works well as a template language with the template syntax.

Render a template

view includes a template file and returns the HTML as a string. ob_start catches the output instead of sending it, and ob_get_clean returns it. extract turns the keys of the array into variables for the template. The template name must always come from the code, never from the visitor.

e is a short name for htmlspecialchars. Every value printed in a template goes through it, so a note with <script> in the title is shown as text.

<?php
// src/view.php
function e(string $value): string {
  return htmlspecialchars($value, ENT_QUOTES | ENT_SUBSTITUTE, 'UTF-8');
}

function view(string $template, array $data = []): string {
  extract($data, EXTR_SKIP);
  ob_start();
  require __DIR__ . '/../views/' . $template . '.php';
  return ob_get_clean();
}

Layout

The layout is the HTML that is shared by all pages. $content is HTML from another view, which is already escaped, so it is printed as it is. <?= is short for <?php echo.

<!-- views/layout.php -->
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title><?= e($title) ?></title>
</head>
<body>
  <?= $content ?>
</body>
</html>

One note

nl2br keeps the line breaks of the note. It is used after e, so the <br> tags are not escaped.

<!-- views/notes/show.php -->
<h1><?= e($note['title']) ?></h1>
<p><?= nl2br(e($note['body'])) ?></p>
<p><a href="/">All notes</a></p>
