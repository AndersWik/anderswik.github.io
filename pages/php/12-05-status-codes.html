Status codes

The status code in the response tells the client how the request went. 2xx means success, 3xx redirect, 4xx an error by the client and 5xx an error on the server. PHP sends 200 by default. http_response_code sets another code, and must be called before any output.

200 OK (Read, Put, Delete)

The request worked and the response has content.

<?php
http_response_code(200);
echo json_encode(["id" => 5, "name" => "Anna"]);

201 Created (Post, Put)

A new resource was created. The Location header tells where it can be found.

<?php
http_response_code(201);
header("Location: /users/5");

202 Accepted

The request was accepted but is not finished yet, for example when it is put in a queue.

<?php
http_response_code(202);

204 No Content (Put, Delete)

The request worked but there is no content to send back.

<?php
http_response_code(204);
exit;

301 Moved Permanently

The page has moved for good. Browsers and search engines remember the new address. The third parameter of header sets the status code.

<?php
header("Location: /foo.php",TRUE,301);
exit;

302 Found

A temporary redirect. header with Location sends 302 if no other code is given. After a form, use 303 See Other so the browser follows it with a GET.

<?php
header("Location: /foo.php");
exit;
<?php
header("Location: /foo.php", true, 303);
exit;

304 Not Modified

The client already has the latest version. It is sent when the ETag the browser has is the same as the current one, and then no body is sent.

<?php
$etag = '"' . md5($content) . '"';
header("ETag: $etag");

if (($_SERVER['HTTP_IF_NONE_MATCH'] ?? '') === $etag) {
  http_response_code(304);
  exit;
}
echo $content;

400 Bad Request

The request is wrong, for example a missing parameter or invalid JSON. 422 Unprocessable Content is often used when the JSON is valid but the values are not.

<?php
http_response_code(400);
echo json_encode(["error" => "id is required"]);

404 Not Found

<?php
http_response_code(404);
echo "Page not found";

500 Internal Server Error

Something went wrong on the server. Log the details and do not show them to the client.

<?php
http_response_code(500);
echo "Something went wrong";

Implementation

Client

The client sends a DELETE with an extra header. CURLOPT_VERBOSE prints the request and response, including the status code, to the terminal.

<?php
$ch = curl_init("http://localhost:8888/");

curl_setopt($ch, CURLOPT_CUSTOMREQUEST, "DELETE");

curl_setopt_array($ch, array(
    CURLOPT_HTTPHEADER  => array('Bazinga: !!!'),
    CURLOPT_RETURNTRANSFER  => 1,
    CURLOPT_VERBOSE     => 1
));

$content = curl_exec($ch);

echo curl_getinfo($ch, CURLINFO_HTTP_CODE) . "\n";

curl_close($ch);

echo $content;

Server

The server answers with a different status code for each method. Start it with php -S localhost:8888.

<?php
switch ($_SERVER['REQUEST_METHOD']) {
  case 'GET':
    http_response_code(200);
    $content = "I am in get";
    break;
  case 'PUT':
    http_response_code(201);
    $content = "I am in put";
    break;
  case 'DELETE':
    http_response_code(200);
    $content = "I am in delete";
    break;
  default:
    http_response_code(405);
    header("Allow: GET, PUT, DELETE");
    $content = "What is ".htmlspecialchars($_SERVER['REQUEST_METHOD']);
    break;
}

echo $content;
